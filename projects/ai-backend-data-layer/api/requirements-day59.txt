# Day59 — Real FastAPI Runtime, PostgreSQL and Alembic Integration.
# Python 3.10+ is REQUIRED (existing ORM code uses PEP 604 `X | Y` union syntax;
# Python 3.9 fails to import it — diagnosed in class, then rerun on Python 3.11).
#
# Two clearly separated scopes:
#
# 1) EXECUTED_LOCAL_RUNTIME unit tests (no database, no Docker) — needs only pytest.
#    `py_compile` does not execute imports, so it works without the runtime stack:
#      cd projects/ai-backend-data-layer/api
#      python3 -m pip install pytest==7.4.3
#      python3 -m py_compile day59_acceptance_logic.py day59_runtime_app.py \
#          test_day59_acceptance_logic.py \
#          day48_alembic/versions/0008_day59_acceptance.py day48_alembic/env.py
#      python3 -m pytest -q test_day59_acceptance_logic.py
#
# 2) INTEGRATION_RUNTIME (OPT-IN; a disposable local PostgreSQL, e.g. a `--rm` Docker
#    container) — needs the FULL runtime stack below. Driver split (matches the runbook):
#      * the FastAPI app uses an ASYNC URL `postgresql+asyncpg://...` -> asyncpg + greenlet
#        (SQLAlchemy's async bridge requires greenlet).
#      * Alembic (`day48_alembic/env.py` run_migrations_online) uses a SYNC URL
#        `postgresql://...` via `DAY48_ALEMBIC_DATABASE_URL` -> the psycopg2 driver.
#    See the Day59 design/runbook for the exact raw-baseline -> stamp -> upgrade ->
#    fresh-connection steps. The disposable database URL/credentials are supplied via env
#    vars at run time and are NEVER committed to the repository.
